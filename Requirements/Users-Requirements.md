# Требования: регистрация, авторизация и управление пользователями

## 1. Регистрация пользователя

Пользователь должен предоставить следующие данные:

### Имя (name)
- Обязательное поле.
- Минимум 3 символа.
- Максимум 50 символов.

### Email
- Обязательное поле.
- Должен быть валидным.
- Должен быть уникальным.
- Формат проверяется через регулярные выражения.

### Пароль
- Обязательное поле.
- Минимум 8 символов.
- Перед сохранением в базе данных должен быть захеширован.
- Используется алгоритм bcrypt.

### Дополнительные требования
- Если email уже существует, пользователю показывается сообщение об ошибке.
- После успешной регистрации пользователь создаётся как ограниченный пользователь (`limited_user`) в PostgreSQL.
- Пользователю назначается роль `limited_user`.

## 2. Авторизация пользователя

Пользователь должен иметь возможность авторизоваться с помощью корректных email и пароля.

### Access Token
- Используется технология JWT.
- Время действия токена — 30 минут.
- Токен должен быть валидным в течение 30 минут с момента авторизации.

### Обработка ошибок
- При некорректном email или пароле возвращается сообщение об ошибке авторизации.

## 3. Просмотр данных пользователя

Обычный пользователь может получать информацию только о себе.

При запросе к `/users/` пользователь видит:
- ID пользователя (UUID).
- Имя пользователя (3–50 символов).
- Email пользователя.
- Роль: `user`.

Супер-администратор может просматривать список всех пользователей системы.

## 4. Повышение пользователя до супер-администратора

Супер-администратор должен иметь возможность повышать других пользователей до роли супер-администратора.

### Требования
- Поле `is_superadmin` изменяется с `False` на `True`.
- Повышение возможно только для зарегистрированных пользователей.
- Пользователь не может повысить самого себя.
- Повышение выполняется через API-запрос с указанием ID пользователя (UUID).

### Требования для доступа
- Пользователь должен быть супер-администратором.
- Bearer Token (JWT) передаётся через заголовок `Authorization`.

## 5. Управление пользователями

Супер-администратор должен иметь возможность просматривать список всех зарегистрированных пользователей.

Список содержит:
- ID пользователя (UUID).
- Имя пользователя (3–50 символов).
- Email пользователя.
- Роль пользователя: `superadmin` или `user`.

### Требования для доступа
- Пользователь должен быть супер-администратором.
- Bearer Token (JWT) передаётся через заголовок `Authorization`.

## 6. Редактирование пользователя

Супер-администратор должен иметь возможность редактировать данные существующих пользователей.

### Доступные для редактирования поля

**Email:**
- Должен быть валидным.

**Имя пользователя:**
- Строка длиной от 3 до 50 символов.

### Дополнительные требования
- Изменение возможно только для зарегистрированных пользователей.
- Пользователь не может редактировать собственные данные через этот метод.

### Требования для доступа
- Пользователь должен быть супер-администратором.
- Bearer Token (JWT) передаётся через заголовок `Authorization`.

### Обработка ошибок
- Если пользователь с указанным ID не найден — `404 Not Found`.
- Если у текущего пользователя недостаточно прав — `403 Forbidden`.

### Успешный ответ
Ответ API должен содержать сообщение об успешности обновления и поля редактируемого пользователя:
- `id`
- `name`
- `email`

## 7. Удаление пользователя

Супер-администратор должен иметь возможность удалять зарегистрированных пользователей.

### Дополнительные требования
- Удаление возможно только для зарегистрированных пользователей.
- Пользователь не может удалить самого себя через этот метод.
- Удаление осуществляется по `user_id` (ID в БД).

### Требования для доступа
- Пользователь должен быть супер-администратором.
- Bearer Token (JWT) передаётся через заголовок `Authorization`.

### Обработка ошибок
- Если пользователь с указанным ID не найден — `404 Not Found`.
- Если у текущего пользователя недостаточно прав — `403 Forbidden`.

### Успешный ответ
Ответ API должен содержать сообщение об успешности удаления пользователя.

## 8. Технические требования

### Имя пользователя (`name`)
- Строка длиной от 3 до 50 символов.
- Ограничение в БД: `NOT NULL`.
- Длина от 3 до 50 символов.

### Email
- Уникальное поле.
- Валидный формат email.
- Проверяется через регулярное выражение.
- Ограничение в БД: `UNIQUE` и `NOT NULL`.

### Пароль
- Строка в виде захешированного bcrypt-хеша.
- Минимальная длина исходного пароля — 8 символов.
- Ограничение в БД: `NOT NULL`.

### ID пользователя (`id`)
- Тип: UUID.
- Генерируется автоматически при создании пользователя.
- Ограничения в БД: `UNIQUE`, `NOT NULL`, `PRIMARY KEY`.

### Роль пользователя (`is_superadmin`)
- Булево значение: `True` или `False`.
- По умолчанию: `False` (обычный пользователь).
